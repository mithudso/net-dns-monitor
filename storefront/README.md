# Net DNS Monitor storefront

The Worker serves the product page, the public Free archive, and private paid orders at https://netdnsmonitor.com/. Cloudflare stores archives in a private R2 bucket and order state in D1. Each order pins the purchased archive. Use a new archive filename for every release and keep previously purchased artifacts available.

## Local checks

Run `node --test storefront/worker.test.mjs` from the repository root using Node.js 24 or newer. The tests exercise the application with SQLite and simulated provider responses. They cover the free download, access denial before payment, webhook validation and replay, reversals, and PayPal capture.

## Release and deployment

1. Build the Free and Premium ZIP archives with `scripts/build_direct_release.py`. Verify both archives on Apple silicon and retain their SHA-256 digests. Upload each to the matching `free/` or `premium/` prefix in `netdnsmonitor-downloads`. Leave both public R2 access methods disabled. Set `FREE_RELEASE` and `PREMIUM_RELEASE` in `wrangler.jsonc` to their exact object keys.
2. Apply the D1 migrations with `npx --yes wrangler@4.164.0 d1 migrations apply netdnsmonitor-orders --remote` from this directory. Deploy with `npx --yes wrangler@4.164.0 deploy` from the same directory. Configure payment secrets through the Cloudflare dashboard or Wrangler secret input. Keep secret values out of Git and command arguments.
3. Download Free from the live storefront and compare its SHA-256 with the release digest. Verify that an unknown order key and direct GET to the Premium route do not serve the archive. Add the Apple listing URL only after the public store lookup finds the shipped app.

## Payment configuration

- **Stripe** requires the `STRIPE_PRICE_ID` of an active one-time USD price equal to `PREMIUM_CENTS`. Add a `STRIPE_API_KEY` restricted to the necessary Checkout Sessions and Payment Intents operations and set `STRIPE_WEBHOOK_SECRET` for `https://netdnsmonitor.com/webhooks/stripe`. Subscribe to `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `charge.refunded`, and `charge.dispute.created`. Enable Apple Pay and Cash App Pay in Stripe where the merchant account and customer are eligible. Hosted Checkout displays the available methods. Live checkout requires `STRIPE_AUTOMATIC_TAX=true`. Set it after verifying the seller’s existing North Carolina registration in Stripe and previewing tax with the product’s approved tax code and an address in that jurisdiction. Stripe only collects in locations with active registrations.
- **PayPal and Venmo** use a separate PayPal Business REST app. Set `PAYPAL_CLIENT_ID` and `PAYPAL_CLIENT_SECRET` as Worker secrets. Configure `STRIPE_TAX_CODE` with the same approved tax code as the Stripe product. The Stripe restricted key also needs write access to Tax Calculations and Tax Transactions. The Worker sends the buyer's billing address to Stripe Tax, stores the quoted tax and calculation ID, and sends the subtotal and tax to PayPal for approval. The Worker requires the same total from PayPal before capture or delivery. Enable `ENABLE_PAYPAL` and, for eligible US merchants and buyers, `ENABLE_VENMO` after verifying the matching payment flow.
- **Off-Stripe tax reporting** runs every ten minutes and retries in case of a transient failure. Use the Stripe Tax report to reconcile PayPal captures and use its reversal API for refunds recorded in PayPal. To find paid PayPal orders that still need reporting, query D1 for `state = 'paid' AND tax_calculation_id IS NOT NULL AND tax_transaction_id IS NULL`. The job retries while the Stripe calculation is valid. Resolve any remaining expired calculations in reconciliation.
- **Sandbox checks** belong on an isolated deployment with its own D1 database and test credentials. Set `BILLING_MODE` to `test`, use the sandbox price and webhook, and use the sandbox domain as `STORE_URL`. Check a successful buyer return, an abandoned order, and a replayed webhook. Enable the live methods only after verifying the corresponding account and payment configuration.

A buyer returns to a private order URL. Stripe webhooks persist payment state independently of that return. The browser can also check Stripe directly if the webhook is still in flight. The PayPal return asks the buyer to confirm capture. Download requires a paid order and the private order key. The key is stored as a hash. For buyer support, verify the provider receipt and match the order reference before helping a buyer recover access.
